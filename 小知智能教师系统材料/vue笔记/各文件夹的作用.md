### 一、优化后的目录核心职责

| 目录      | 职责说明                                                     | 边界补充（关键）                                       |
| --------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| `entity/` | 核心业务实体的类型定义（接口、枚举、类型别名），纯类型描述，无任何逻辑 / 状态 | 仅做类型约束，不包含值、函数、响应式数据               |
| `data/`   | 业务数据管理（静态常量、响应式状态、数据请求封装、数据缓存） | 聚焦「数据存储 / 获取」，不包含 UI / 表单逻辑          |
| `forms/`  | 表单专属逻辑（验证规则、表单实例、模态框控制、提交 / 重置 / 回显逻辑） | 仅封装表单相关，不包含数据请求（可调用 data 层的请求） |
| `utils/`  | 通用工具函数（纯函数），与业务解耦，可全局复用               | 无副作用、不依赖业务状态、输入输出可预测               |
| `hooks/`  | 复用性强的业务逻辑钩子（整合数据 + 逻辑，对外暴露状态 / 方法） | 封装「可复用的业务流程」，如分页、筛选、列表操作       |
